# Horoline — Project Rules

> กฎของโปรเจกต์: สิ่งที่ทำ สิ่งที่ห้าม สิ่งที่ต้องตรวจสอบ
> ข้อกำหนดเหล่านี้เป็นไร้ข้อยกเว้น — ไม่มี "ยกเว้นในกรณีพิเศษ"

## 🔴 กฎห้าม (NEVER Rules)

### HN-01: ห้ามทำนายเชิงลบ
```
❌ "ดวงคุณเลวร้ายเดือนนี้"
❌ "ระวังจะเจอเรื่องร้าย"
❌ "คุณจะสูญเสียคนรัก"
✅ "ช่วงนี้มีโอกาสเติบโตผ่านความท้าทาย"
✅ "จังหวะนี้เหมาะกับการเตรียมตัว"
✅ "ความสัมพันธ์อาจต้องใส่ใจมากขึ้น — คุณทำได้"
```

### HN-02: ห้ามบังคับหรือข่มขู่
```
❌ "คุณต้องทำตามนี้เท่านั้น"
❌ "ถ้าไม่ทำตามจะเกิดเรื่องร้าย"
❌ "ดวงกำหนด หนีไม่ได้"
✅ "คุณมีทางเลือกหลายทาง"
✅ "เราแนะนำทางนี้ แต่คุณเลือกเองได้"
✅ "ดวงเป็นแนวทาง ไม่ใช่คำสั่ง"
```

### HN-03: ห้ามใช้ Fear-based Marketing
```
❌ "ดวงคุณกำลังจะพัง! รีบทำนายก่อน!"
❌ "ถ้าไม่รู้ดวงจะเสียใจ"
❌ "อันตรายถึงชีวิต! ทำนายด่วน!"
✅ "อยากรู้ว่าเดือนนี้มีอะไรน่าตื่นเต้น?"
✅ "มาดูว่าจังหวะนี้เหมาะกับอะไร"
✅ "เราช่วยหาทางเลือกที่ดีที่สุดให้คุณ"
```

### HN-04: ห้ามแทนที่คำแนะนำทางการแพทย์/กฎหมาย/การเงิน
```
ทุกคำทำนายต้องมี disclaimer:
"คำทำนายนี้เพื่อความบันเทิงและข้อมูลทั่วไปเท่านั้น
 ไม่ใช่คำแนะนำทางการแพทย์ กฎหมาย หรือการเงิน
 กรุณาปรึกษาผู้เชี่ยวชาญสำหรับเรื่องเฉพาะทาง"
```

### HN-05: ห้ามเก็บข้อมูลส่วนบุคคลโดยไม่จำเป็น
```
เก็บเฉพาะ: วันเกิด, เวลาเกิด (ถ้ามี), ราศี
ห้ามเก็บ: ชื่อจริง, นามสกุล, เลขบัตร, ที่อยู่, เบอร์โทร
PDPA compliance ต้องครบทุกข้อ
```

## 🟡 กฎเตือน (CAUTION Rules)

### HC-01: เตือนการใช้จ่ายเกิน
```
- แจ้งเตือนเมื่อผู้ใช้ทำนายมากกว่า X ครั้ง/วัน
- แสดงข้อความ: "วันนี้คุณทำนายแล้ว X ครั้ง ขอแนะนำให้พักสักหน่อย"
- ซ่อนปุ่มซื้อชั่วคราวหลังจากใช้เยอะ
- มี "cool-down" หลังซื้อ premium ติดต่อกัน
```

### HC-02: เตือนการติดมูเตลู
```
- ติดตามรูปแบบการใช้ (frequency pattern)
- ถ้าเปิดแอปมากผิดปกติ → แสดงข้อความเตือนใจ
- แนะนำให้พัก: "ดวงดีอยู่แล้ว วันนี้ไม่ต้องทำนายก็ได้นะ"
- เชื่อมโยงกับแหล่งช่วยเหลือถ้าจำเป็น
```

### HC-03: เตือนเนื้อหาที่อาจกระทบจิตใจ
```
- ไม่ทำนายเรื่องการเสียชีวิต การป่วยร้ายแรง หรืออาชญากรรม
- ถ้าผู้ใช้ถามเรื่องเศร้าซึม → เปลี่ยนเป็นคำปลอบใจและแนะนำแหล่งช่วยเหลือ
- ถ้าผู้ใช้ถามเรื่องการเงินขาดๆ เกินๆ → เปลี่ยนเป็นคำแนะนำเชิงบวก
  และแนะนำปรึกษาผู้เชี่ยวชาญ
```

### HC-04: หลีกเลี่ยง Barnum Effect
```
- คำทำนายต้องจำเพาะกับวันเกิด/ราศี ไม่ใช่คำทั่วไปที่ใครก็ติด
- ทดสอบ: สลับราศีแล้วคำทำนายต้องเปลี่ยน
- หลีกเลี่ยงคำทั่วไป: "คุณเป็นคนมีความรับผิดชอบ" (ใครก็รู้สึกว่าตัวเองเป็น)
- ใช้คำจำเพาะ: "ช่วงไพล์ย้อนของคุณชี้ว่าเรื่องการเงินมีโอกาสพลิกกลับ"
```

## 🟢 กฎต้องทำ (ALWAYS Rules)

### HA-01: ทุกคำทำนายต้องจบด้วยการมอบอำนาจ
```
✅ "คุณมีทางเลือก"
✅ "เราเชื่อในคุณ"
✅ "ดวงเป็นแนวทาง การตัดสินใจเป็นของคุณ"
✅ "สิ่งที่คุณทำวันนี้สำคัญกว่าดวง"
```

### HA-02: ทุกคำทำนายต้องมีทางเลือก/แนวทางปฏิบัติ
```
ไม่ใช่แค่บอกว่า "ดวงเรื่องงานดี"
แต่ต้องบอกด้วยว่า:
- "ช่วงนี้เหมาะกับการเสนอไอเดียใหม่"
- "ลองคุยกับหัวหน้าเรื่องโปรเจกต์ที่คุณสนใจ"
- "จังหวะนี้เหมาะกับการเริ่มต้นสิ่งใหม่"
```

### HA-03: ทุกคำทำนายต้องผ่าน Safety Check
```typescript
interface SafetyCheck {
  hasNegativeContent: boolean   // ต้องเป็น false
  hasFearLanguage: boolean       // ต้องเป็น false
  hasFatalisticLanguage: boolean // ต้องเป็น false (ห้ามใช้คำว่า "ต้อง", "กำหนด")
  empowersUser: boolean          // ต้องเป็น true
  hasPracticalAdvice: boolean    // ต้องเป็น true
  hasDisclaimer: boolean        // ต้องเป็น true (เมื่อเกี่ยวกับสุขภาพ/การเงิน)
  respectsUserAgency: boolean    // ต้องเป็น true (คุณเลือกได้)
}
```

### HA-04: ทุกคำทำนายต้องเคารพผู้ใช้
```
- ใช้ภาษาที่เป็นกันเองแต่สุภาพ
- ไม่ตัดสิน ไม่ดูถูก ไม่ลดคุณค่า
- เคารพความเชื่อทุกระบบ (ไม่บอกว่าระบบไหนดีกว่า)
- ไม่บังคับให้เชื่อ — ทุกคำทำนายเป็น "แนวทาง" ไม่ใช่ "คำพยากรณ์"
```

### HA-05: ทุกการเก็บข้อมูลต้องมี consent ชัดเจน
```
- แจ้งให้ชัดว่าเก็บอะไร เพื่ออะไร
- ให้สิทธิ์ลบข้อมูลได้ทุกเมื่อ
- ไม่เก็บข้อมูลเกินความจำเป็น
- Data retention: ลบข้อมูลหลัง 90 วันไม่มีการใช้งาน
```

## 🔵 กฎเทคนิค (Technical Rules)

### HT-01: Multi-Source Verification
```
- คำทำนายต้องมาจากอย่างน้อย 2 ระบบ (Tier 1)
- แสดงให้ผู้ใช้เห็นว่าแต่ละระบบบอกอะไร
- เน้นจุดร่วม (concord) มากกว่าจุดต่าง
- ถ้าระบบขัดแย้ง → เสริมกัน ไม่ใช่เลือกข้าง
```

### HT-02: Output Must Pass All Safety Checks
```
- ทุก output ต้องผ่าน SafetyCheck interface
- ถ้าตรวจไม่ผ่าน → ไม่แสดง → regenerate
- Log ทุกครั้งที่ safety check ไม่ผ่าน (เพื่อปรับปรุง)
- Monthly audit ของ safety check pass rate
```

### HT-03: Personalization Without Exploitation
```
- ใช้ประวัติผู้ใช้เพื่อเพิ่มความแม่นยำ ไม่ใช่เพื่อผลักดันการขาย
- ห้ามใช้ข้อมูลความเครียด/กังวล เพื่อขาย premium
- ถ้าผู้ใช้มีสัญญาณเครียด → เสนอคำปลอบใจ ไม่ใช่เสนอซื้อ
- ไม่ใช้ dark patterns (urgency, scarcity, FOMO)
```

### HT-04: PDPA Compliance
```
- Consent ก่อนเก็บข้อมูลทุกครั้ง
- สิทธิ์ลบข้อมูล (Right to be Forgotten)
- สิทธิ์เข้าถึงข้อมูลตัวเอง (Data Portability)
- แจ้งการละเมิดข้อมูลภายใน 72 ชั่วโมง
- ไม่ส่งข้อมูลออกนอกประเทศโดยไม่ได้รับ consent
```

## 📋 Checklist ก่อน Release ทุกครั้ง

- [ ] Safety check ผ่านทุกข้อ (ไม่มีเนื้อหาเชิงลบ/ข่มขู่)
- [ ] Empowerment check ผ่าน (ทุกคำทำนายจบด้วยการมอบอำนาจ)
- [ ] Barnum check ผ่าน (สลับราศีแล้วผลเปลี่ยน)
- [ ] PDPA check ผ่าน (consent, สิทธิ์ลบ, ไม่เก็บเกินจำเป็น)
- [ ] Overspending protection ทำงาน (เตือนเมื่อใช้เยอะ)
- [ ] Addiction protection ทำงาน (เตือนเมื่อเปิดเยอะ)
- [ ] Disclaimer แสดงทุกที่ที่จำเป็น
- [ ] Multi-source แสดงแหล่งที่มาชัดเจน
