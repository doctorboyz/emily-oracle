## Lessons Learned

- **Cross-cutting concerns ไม่ต้องการ repo ใหม่**: ถ้าความสามารถแจกจ่ายได้ตาม existing boundaries อย่าสร้าง bounded context ใหม่
- **ทดสอบทันทีหลังเขียน**: โดยเฉพาะ shell scripts ที่มี string interpolation ซับซ้อน — heredoc JSON ควร verify ทีละ field
- **GitHub Issues เป็น lightweight registry ได้**: ไม่ต้องมี database กลาง — label `kappanet:birth` ทำให้ค้นหาง่าย และ `gh` CLI ทำให้ดึงข้อมูลได้โดยไม่ต้อง API พิเศษ
