## Honest Feedback

**Friction 1**: The settings.local.json warning format was confusing — the error said "Use 'Pip upload --skip-existing'" which suggests capitalizing the first letter, but the actual fix required `Bash(...)` wrapping. The error message could be more helpful.

**Friction 2**: The kappa-skill-cli doesn't have a clear "add a new skill" workflow. I created the directory and SKILL.md manually. There's `kappa-skill-cli init` but that seems to be for initializing a new Cell, not adding a skill to the distribution. The installer.ts has profile counts hardcoded — this means every new skill needs manual updates in multiple places. Classic case where /surgery itself would be useful.

**Friction 3**: Context cost for exploration was high. I read 8+ CLAUDE.md files and SKILL.md files before writing one. Necessary for consistency, but I wonder if a condensed "kappa skill format reference" document would save future sessions from re-reading everything.

## Lessons Learned

- Kappa permission deny rules must use `Bash(pattern *)` format with closing parentheses
- The 5 Kappa strands have a clear dependency hierarchy: DNA is the root, all strands inherit from it
- Kappa skills follow a consistent format: frontmatter → medical metaphor → invocation → flags → workflow → rules → notes
- The Change Impact Matrix pattern (change type → affected components) is reusable for any multi-repo ecosystem
