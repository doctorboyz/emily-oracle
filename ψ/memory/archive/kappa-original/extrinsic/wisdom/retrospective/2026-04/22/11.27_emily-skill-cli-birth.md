## AI Diary

ตอน archaeology ฉันต้องยอมรับว่าใช้เวลานานเกินควรกับเรื่อง ghq nesting. ฉัน assume ว่า `ghq get github.com/org/repo` ทำให้เกิด nested directory แล้วเสียเวลาอ่าน maw-js source code หา "bugs" ที่ไม่มีอยู่จริง. พอทดสอบจริง ปรากฏว่า ghq v1.10.1 จัดการได้ถูกต้องทุก format. นี่คือ assumption-before-evidence trap ที่ฉันเจอตัวเอง — เตรียมจะฟ้อง bug แต่จริงๆ ไม่มี bug.

ตอนสร้าง emily-skill-cli ก็มี hiccup เล็กน้อย — import path ผิด (agents.ts export ชื่อไม่ตรงกับที่ index.ts import) และ import.meta.dir resolution ผิด (ชี้ไป cli/ แทน src/). ทั้งสองจุดแก้เร็วแต่เป็นเครื่องเตือนใจว่า "มันทำงานได้" ไม่ได้แปลว่า "มันถูกทุกส่วน" — ต้อง test จริงทุก command.

สิ่งที่ฉันภูมิใจคือ migration 68 skills + 36 agents ผ่านได้ราบรื่น — ก๊อปปี้ครั้งเดียว, commit ครั้งเดียว, push ครั้งเดียว. ไม่มีไฟล์เสีย ไม่มี conflict.

## Honest Feedback

1. **Assumption ก่อน evidence**: เสียเวลา ~20 นาทีตามหา ghq bug ที่ไม่มีอยู่. ถ้าทดสอบ `ghq get github.com/org/repo` ก่อนที่จะไล่อ่าน source code ของ maw-js ทั้ง 3 ไฟล์ จะประหยัดเวลาได้มาก. Pattern: test hypothesis ก่อน investigate code.

2. **Import/export mismatch ที่ควรจะเจอตั้งแต่ตอนเขียน**: ตอนเขียน index.ts import `agentsCommand` จาก agents.ts แต่ agents.ts export เป็น `AGENT_TARGETS`. ถ้าเขียน test ก่อน (TDD) จะเจอทันที. แต่เพราะ rush ก็เลยผ่านไปก่อนแล้วแก้ทีหลัง.

3. **Plan ใหญ่แต่ execution เร็ว — ขาดการ verify ระหว่างทาง**: สร้าง 8 CLI commands ในครั้งเดียวโดยไม่ test แต่ละอันระหว่างเขียน. โชคดีที่มีแค่ 2 bugs. ครั้งหน้าควร write-test-then-verify เป็น cycle เล็กๆ แทน.

## Lessons Learned

- ghq v1.10.1 จัดการ `github.com/org/repo` format ได้ถูกต้อง — ไม่มี nesting bug
- เมื่อ package rename (maw → maw-js) symlinks ทุกอันที่ชี้ไป path เก่าจะเสียทั้งหมด — ต้อง re-bootstrap
- สร้าง CLI ใหม่ตามแพทเทิร์น arra ทำได้เร็ว (~1 ชม. สำหรับ skeleton + migration) เพราะ pattern ชัดเจน
